# HA Device: Multi-Entity Home Assistant Integration

**Created:** 2026-02-15
**Status:** planned

## Goal

Replace the single MQTT sensor with a proper Home Assistant **device** (`watermeter_ai`) containing ~21 entities. All entities share one state topic (JSON payload) with `value_template` extraction. Training data stats are published on a slower cadence.

- **`watermeter_service.py` L1621-1656** — `publish_to_mqtt()` publishes a JSON payload with `state` (rounded m3) and `attributes` (last_update, warnings, leak_warning, confidences).

- **`current_state` dict (L47-62)** — already tracks: `total_value`, `status`, `processing`, `leak_warning`, `last_rejected_value`, `last_rejected_reasons`, `last_published_value`, `last_published_timestamp`, `warnings`, `predictions`.

## Architecture

### MQTT Topics

- **State topic** (shared): `homeassistant/sensor/watermeter/state` (from `ha_config['publish_topic']`)
  - All entities use `value_template` to extract their value from the JSON payload.
- **Training stats topic**: `homeassistant/sensor/watermeter/training_stats`
  - Separate topic for slow-cadence entities (7-10) to avoid unnecessary updates.
- **Discovery topics**: `{discovery_prefix}/{component}/watermeter_ai/{object_id}/config`
  - One per entity, published with `retain=True`.

### JSON Payloads

**State payload** (published every reading):
```json
{
  "state": 123.4567,
  "state_raw": 123.456789,
  "leak": false,
  "min_confidence": 95.3,
  "status": "ok",
  "rejections": 0,
  "last_rejected": null,
  "last_rejected_reason": "",
  "avg_rate": 0.042,
  "last_update": "2026-02-15T10:30:00",
  "mqtt_connected": true,
  "processing": false,
  "confirmation_pending": false,
  "inference_ms": 245,
  "processing_s": 3.2,
  "model_digits": "model_digits_resnext50_r128",
  "model_arrows": "model_arrows_efficientnet_r128"
}
```

**Training stats payload** (published on slow cadence):
```json
{
  "unlabeled_digits": 42,
  "unlabeled_arrows": 17,
  "training_digits": 1250,
  "training_arrows": 3400
}
```

### Discovery Message Structure

Each entity discovery message follows this pattern:
```json
{
  "name": "Entity Name",
  "unique_id": "watermeter_ai_xxx",
  "state_topic": "homeassistant/sensor/watermeter/state",
  "value_template": "{{ value_json.field_name }}",
  "device": {
    "identifiers": ["watermeter_ai"],
    "name": "DIY AI Water Meter",
    "manufacturer": "with Claude Code",
    "model": "OpenVINO Inference"
  },
  "entity_category": "diagnostic",
  ...
}
```

The `device` block is identical across all entities -- HA groups them automatically.

For binary sensors, use `payload_on` / `payload_off` with `true` / `false` and appropriate `value_template`:
```json
{
  "payload_on": true,
  "payload_off": false,
  "value_template": "{{ value_json.leak }}"
}
```

For the status enum sensor, use `options`:
```json
{
  "options": ["idle", "ok", "warning", "error", "no_models", "pending_confirmation", "processing"],
  "device_class": "enum"
}
```

For training stats entities (7-10), use the separate `training_stats` state topic.

   def publish_training_stats(self):
       """Publish training data statistics to HA via MQTT (slow cadence)."""
       if not self.ha_publish_enabled or not self.mqtt_client or not self.mqtt_client.is_connected():
           return

       ha_config = self.config["homeassistant"]
       training_path = Path(self.config.get("low_confidence", {}).get("save_path", "/training"))

       # Count files (same logic as routes/models.py get_training_data_stats L231-264)
       digits_input = training_path / "digits" / "input"
       arrows_input = training_path / "arrows" / "input"
       digits_gt = training_path / "digits" / "ground_truth"
       arrows_gt = training_path / "arrows" / "ground_truth"

       payload = {
           "unlabeled_digits": len(list(digits_input.glob("*.jpg"))) if digits_input.exists() else 0,
           "unlabeled_arrows": len(list(arrows_input.glob("*.jpg"))) if arrows_input.exists() else 0,

       }

       topic = ha_config["publish_topic"].rsplit("/", 1)[0] + "/training_stats"

       logger.info(f"Published training stats to {topic}")
