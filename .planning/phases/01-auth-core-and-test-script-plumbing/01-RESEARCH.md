### Locked Decisions

**Already locked (research + requirements; do not re-open)**
- Default-deny pure-ASGI auth middleware with an allowlist: `/health`, `/login`, `/setup` (only while unconfigured), `/logout`, `/static/*`. `docs_url`, `redoc_url` and `openapi_url` are disabled. A route-inventory test walks `app.routes`.
- Custom signed cookie using stdlib `hmac`, with a password epoch. `hashlib.scrypt` with an explicit `maxmem`, stored as a PHC-style string. The hash, signing secret and instance ID live in `/data/auth.json` (mode 0600, atomic write), never in `config.yaml`.
- CSRF: an Origin / `Sec-Fetch-Site` check on unsafe methods, plus a required `X-Requested-With: watermeter` on cookie-authenticated `/api/*` writes. `/login` and `/setup` form posts get the Origin check only.
- The 401 contract depends on the caller:
  - full pages get a 303 to `/login?next=…`, with `next` validated as same-origin;
  - HTMX gets a 401 plus `HX-Redirect`;
  - `/api/*` gets a JSON 401.
  `static/auth.js` patches fetch and XHR, adds the CSRF header and redirects on 401.
- `WATERMETER_ADMIN_PASSWORD` (or `_FILE`) is seed-only. It is ignored once a hash exists.
- There is no auth-disable switch anywhere in production code.

- **D-16:** The cookie name is unique per instance, `wm_session_<8 hex>`. The suffix is a random instance ID generated with the secret on first start and stored in `auth.json`. ## Summary

The approach was already locked by project research, and this session closed the three open spikes from STATE.md with real evidence. (1) `hashlib.scrypt` works on the shipped image (Python 3.10.12 / OpenSSL 3.0.2): the default `maxmem` rejects N=2^15 with `ValueError: ... memory limit exceeded` and an explicit `maxmem` fixes it. OWASP lists N=2^15, r=8, p=3 as an equal-strength configuration; it measured about 205 ms on this host. (2) htmx 1.9.10 handles `HX-Redirect` before it looks at the status code, so a 401 plus `HX-Redirect` navigates the browser and never swaps the body. (3) In headless Chrome over plain HTTP on a LAN IP, `Origin` is sent on same-origin POSTs (fetch, XHR, form) and `Sec-Fetch-*` is absent. A cross-site simple POST arrives with a foreign `Origin` that the server can reject, and a cross-site request with a custom header is stopped at the CORS preflight. A throwaway gate + cookie + CSRF prototype passed on both Starlette 0.52.1 (local venv) and 1.7.0 (shipped image, and what CI resolves).

The work is about 400 lines of new stdlib code plus templates, one small JS shim, one CLI subcommand and a lot of plumbing. The riskiest parts are not the crypto: they are (a) landing the gate, `auth.js`, setup/login pages and the fixture changes together so `main` never publishes a `:dev` image that locks users out, (b) a file-ownership trap in the recovery CLI (`docker exec` runs as root and the image has `USER root`, so a root-owned 0600 `auth.json` would be unreadable by the app), and (c) failing closed when `auth.json` exists but is unreadable, instead of falling back to the open setup page.

**Primary recommendation:** Implement exactly the locked design as one pure-ASGI `AuthMiddleware` (CSRF check first, then gate) plus a leaf `auth.py` store, using N=2^15/r=8/p=3 scrypt, a session-scoped precomputed hash and directly minted cookie in the unit fixtures (no per-test hashing), and land gate + shim + pages + fixtures + scripts in an order where `main` is never half-wired.

### Pattern 1: Default-deny gate with a three-state store
**What:** One `AuthMiddleware` class. The store reports `UNCONFIGURED`, `CONFIGURED`, or `UNAVAILABLE`.
**Rules:**
- `UNAVAILABLE` means `auth.json` exists but cannot be read or parsed. **Fail closed:** serve only `/health`, return 503 plus a log line for the rest. Never fall back to the open setup page. Recovery is the documented "delete the file" path.
- `UNCONFIGURED` (no file, or file without `password_hash`): allow `/health`, `/setup`, `/static/*`. Everything else redirects/denies toward `/setup`. `GET /login` redirects to `/setup`.
- `CONFIGURED`: allow `/health`, `/login`, `/logout`, `/static/*`. `/setup` is **not** allowlisted, so it falls to default-deny for anonymous callers; the handler additionally redirects authenticated callers to `/` and never renders the form.
- Unknown paths (404s) are denied before routing, so anonymous probes learn nothing about which routes exist.
- Treat `HEAD`/`OPTIONS` like `GET`. A CORS preflight from a foreign origin therefore gets 303/401 with no CORS headers and fails, which is what we want.
- `websocket` scope: close with code 1008 (the app has no websockets; default-deny anyway).
**State caching:** `os.stat` per request on `auth.json` (microseconds) and re-parse only when `(st_mtime_ns, st_size, st_ino)` changes. This makes the host-access CLI take effect on a running server immediately and makes epoch bumps by another process visible. Resolve the path at call time (`WATERMETER_AUTH_FILE` env, default `/data/auth.json`), never at import time, because the unit tests import the process-global `app` once and the conftest mocks `watermeter.watermeter_service`.

### Pattern 2: AuthStore file format and writes
**File (`/data/auth.json`, mode 0600):**
```json
{"version": 1, "password_hash": "$scrypt$ln=15,r=8,p=3$<b64 salt>$<b64 hash>", "session_secret": "<64 hex>",
 "instance_id": "<8 hex>", "epoch": 1, "created_at": "<UTC ISO>"}
```
- PHC-style, unpadded base64, parameters inside the string so a later move to argon2 is a rehash-on-login change.
- `maxmem` is computed from the **parsed** parameters (`2 * 128 * r * (n + p + 2)`). Clamp parsed `ln` to ≤ 17 and `r`,`p` to small caps before hashing, so a tampered file cannot request gigabytes.
- **First creation (setup, env seed, CLI on a missing file) must be no-clobber:** write a `mkstemp` file in the same directory, then `os.link(tmp, final)` (raises `FileExistsError` if someone else won), then unlink tmp. Wrap "check configured → create" in a module-level `threading.Lock`. The second of two concurrent submits gets a refusal. (AUTH-02.)
- **Replacements (change password, CLI on an existing file)** use `os.replace` of a same-directory temp file, bumping `epoch` and keeping `session_secret` and `instance_id`.
- **Ownership:** after creating the temp file, if `os.geteuid() == 0`, `os.chown(tmp, st.st_uid, st.st_gid)` copying the owner of the parent directory (or of the existing file). See Pitfall 1.
- Secret/instance ID are created together with the first hash (not at process start): unconfigured instances have no sessions, so there is nothing to sign yet. Deleting the file for recovery therefore also rotates the secret and cookie name, which orphans every old cookie (desired).
- Warn once at startup when `/data` is not a mount (`os.path.ismount`), unless the password comes from the env seed (the seed re-applies on every recreate). `[VERIFIED: ismount False without volume, True with bind mount]`.

### Pattern 3: Signed session token with epoch (verified in prototype)
`v1.<issued>.<epoch>.<hex hmac-sha256(secret, "v1.<issued>.<epoch>")>`; valid when the signature matches (`hmac.compare_digest`), `epoch == store.epoch`, and `now - issued ≤ 30 d`. When `now - issued > 15 d` on a valid request, the `send` wrapper appends a fresh `Set-Cookie` (same attributes). Cookie attributes: `Path=/`, `Max-Age=2592000`, `HttpOnly`, `SameSite=Lax`, `Secure` iff `request.url.scheme == "https"`. Stateless: logout clears only this browser's cookie; a stolen cookie lives until expiry or an epoch bump (accepted for a single-admin home device; document).

### Pattern 4: 401 contract by caller (verified in prototype)
Decision order in `_deny`: `HX-Request: true` → `401`, empty body, `HX-Redirect: /login?next=<page>`; else path starts with `/api/` → `401` JSON `{"success": false, "message": "Authentication required"}` (keys match the app's existing `success`/`message` error contract; add `"setup_required": true` in the unconfigured state); else → `303` to `/login?next=<path+query>` (or `/setup`).
- All 53 write routes and every JSON endpoint are under `/api/`; the only non-`/api/` routes are the seven HTML pages and `/health` `[VERIFIED: grep of @router.post/delete/put/patch decorators: no write route outside /api/]`.
- For HTMX, derive the page for `next` from `HX-Current-URL` (full URL): keep only path+query, require its netloc to equal the `Host` header, otherwise `/`. The requested fragment URL (`/api/status/html`) must never be the `next` target.
- `safe_next(value)`: must start with a single `/`, not `//`, no `\`, no control characters, and must not point at `/login`, `/setup`, `/logout`; otherwise `/`. Apply on the way out of every redirect that uses it, including the hidden `next` form field on `POST /login`. Success is `303`, not `307`, so the browser does not replay the POST.

### Pattern 5: CSRF = Origin/Sec-Fetch-Site + custom header
For `POST/PUT/PATCH/DELETE`:
1. `Sec-Fetch-Site` present → only `same-origin` or `none` pass (`same-site` is rejected: other ports on the same host are same-site).
2. Else `Origin` present → `null` rejected; otherwise `netloc` of the origin must equal the request `Host` header (compare netloc only, not scheme, so a TLS-terminating proxy that does not forward `X-Forwarded-Proto` to uvicorn still works).
3. Neither header → treated as a non-browser client and allowed by this step.
4. Additionally, a request that **carries a valid session cookie** and targets `/api/*` must have `X-Requested-With: watermeter`, else 403 JSON. This closes the "browser omits Origin" gap for cookie-bearing requests without touching `/login`, `/setup`, `/logout` (Origin check only, per the locked decision).
- Put this check **before** the auth gate so forged cross-site writes get 403 regardless of login state.
- Reverse proxies that rewrite `Host` (nginx default `proxy_set_header Host $proxy_host`) will fail rule 2. Recommend an env var `WATERMETER_ALLOWED_ORIGINS` (comma-separated origins) plus a README note to preserve `Host`. Not a config-schema key (see A2).
- Do not read `X-Forwarded-Host`.
- No GET route mutates state `[VERIFIED: the 36 GET routes listed; none is named trigger/reset/start/clear/delete]`, which keeps `SameSite=Lax` sufficient for top-level navigations.

### Pattern 6: Setup, login, logout, change-password, seed, token
- **GET /setup (unconfigured):** card with password + confirm (+ token field iff `WATERMETER_SETUP_TOKEN_REQUIRED=1`). Show the D-06 notice when `Path("/data/reference_raw.jpg").exists() or Path("/data/state.json").exists()` (see A4; `reference_raw.jpg` is what `routes/pages.py:43` tests for first-run). No `_nav.html`, no `auth.js`.
- **POST /setup:** Origin check (middleware) → body cap (16 KiB, enforced by counting bytes in a wrapped `receive`, because `Content-Length` may be absent) → validate (≥ 8, ≤ 1024 chars, match) → token check with `hmac.compare_digest` when required (wrong/missing: log the token per D-09 and count a failure in the limiter) → `await asyncio.to_thread(hash)` → lock → re-check unconfigured → no-clobber write → issue session cookie → `303 /` (D-10). Refusals when already configured: `303 /` (authenticated) or the gate's denial.
- **POST /login:** limiter pre-check first (429 + `Retry-After` **before** any hashing) → verify in a thread (`hmac.compare_digest` on the derived key; cap length at 1024) → on failure record in limiter, `logger.warning(f"Failed login from {ip}")` (never the password), re-render with generic "Wrong password" and status 401 → on success reset that IP's counters, issue cookie, `303 next`.
- **POST /logout:** HTML form in `_nav.html` and `account.html`; clears the cookie (`Max-Age=0`), `303 /login`.
- **POST /api/auth/password (JSON via `account.js` + `auth.js`):** current + new + confirm; verify current in a thread (failures go to the same limiter, prefixed key); on success write with `epoch+1`, return `{success: true}` and `Set-Cookie` with the new epoch (D-03).
- **Env seed:** in `lifespan`, `auth.bootstrap_from_env()` inside `try/except Exception` that logs and continues (D-07: a failure must never stop the reading loop). Only acts when the state is UNCONFIGURED. `_FILE` variant: strip one trailing newline. Apply the same ≥ 8 rule; on violation log an error and stay in setup state (A3).
- **Setup token:** `secrets.token_hex(8)` generated in memory at startup when the flag is set; logged at WARNING at startup and on each wrong/missing-token attempt; never written to disk or placed in a URL; ignored when the password came from the env seed.

### Pattern 7: Failure-only throttle (Frigate numbers)
Per client IP (`request.client.host`, never `X-Forwarded-For`): block when failures within the last 1 s ≥ 1, 60 s ≥ 5, or 3600 s ≥ 20. Add a global backstop with generous numbers (A1). `Retry-After` = max over tripped windows of `oldest + window - now`, rounded up. Success clears only that IP's list. Counts failures of login, setup-token, and change-password. Bounded to 1024 keys with oldest eviction, `threading.Lock`, injectable clock for tests. HTMX polling 401s and anonymous GETs never count. Recovery from a throttle is time; there is no account lockout.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Password KDF | A custom hash or iterated SHA | `hashlib.scrypt` (PHC string) | Memory-hard, in stdlib, OWASP-listed parameters |
| Constant-time comparison | `==` on tokens, hashes, setup token, env password | `hmac.compare_digest` | Timing side channels |
| Randomness | `random`, `uuid4` for secrets | `secrets.token_hex` / `token_bytes` | CSPRNG |
| Atomic, no-clobber file creation | `exists()` then `open("w")` | `mkstemp` in the same dir + `os.link` (create) / `os.replace` (update) | Closes the check-then-write race (AUTH-02); matches `persistence.py`'s existing temp+`os.replace` idiom |
| Cookie parsing and `Set-Cookie` formatting | Manual header string handling for the response | `HTTPConnection(scope).cookies`; `Response.set_cookie`; `MutableHeaders(scope=message).append("set-cookie", ...)` for the refresh path | Verified on Starlette 0.52.1 and 1.7.0 |
| Form parsing | Manual body parsing | `await request.form()` (`python-multipart` is already installed) | Plus a byte-counted body cap |
| Open-redirect defense | Ad-hoc `startswith("/")` | One `safe_next()` with tests (`//`, `/\`, `https://`, control chars, `/login`) | Applied on every redirect that uses `next` |
| Pre-auth CSRF tokens in templates | Per-template token plumbing | `X-Requested-With` via `auth.js` + Origin check | Seven standalone templates, no base layout |
| Throttle | A fixed-window counter | Sliding windows over failure timestamps (`deque`) | Fixed windows allow double bursts at the boundary |
| Third-party auth/session/CSRF libs | `passlib`, `fastapi-users`, `starlette-csrf`, `SessionMiddleware` | The locked stdlib design | One admin, no DB, plain-HTTP LAN; libraries add dependencies and wrong defaults |

**Key insight:** every piece is small, but all must agree on one set of facts (cookie name, epoch, state names, allowlist). Keep them in `auth.py` constants and import them everywhere (middleware, routes, `auth.js` redirect target, tests), instead of repeating strings.

## Common Pitfalls

### Pitfall 1: `docker exec` runs as root and leaves an unreadable `auth.json`
**What goes wrong:** The README recovery path is `docker exec <container> python3 -m watermeter set-password`. `docker exec` defaults to the image's user, and the Dockerfile has `USER root` (line 2) with no later `USER`; the app itself runs as `watermeter` via `exec gosu watermeter "$@"` in the entrypoint. A root-created `0600` file (or a root-owned temp file `os.replace`d over the old one) is unreadable by the app. With a naive store this looks like "no password" and reopens setup, or breaks login until the next restart (the entrypoint's `chown -R watermeter:watermeter ... /data` fixes it only then).
**How to avoid:** (a) `chown` the new file to the parent directory's owner when `geteuid() == 0` (works with `PUID`/`PGID` remaps, because the entrypoint chowns `/data` to the remapped user); (b) document `docker exec -u watermeter`; (c) fail closed on an unreadable file (Pattern 1).
**Warning signs:** after running the CLI, `ls -l /data/auth.json` shows `root root`; login stops working until restart.

### Pitfall 2: Unreadable or corrupt `auth.json` treated as "not configured"
**What goes wrong:** `json.load` raises, the store returns "no password", and `/setup` opens to anyone on the LAN.
**How to avoid:** Three states, not two. A file that exists but cannot be read/parsed/validated is `UNAVAILABLE`: 503 for everything but `/health`, loud log line naming the file, README recovery = delete or fix it. Only `FileNotFoundError` (or a valid file without `password_hash`) means unconfigured.

### Pitfall 3: Landing the gate without its counterparts breaks `:dev`, tests or CI
**What goes wrong:** Every push to `main` runs CI and publishes `:dev` (project CLAUDE.md). A commit that enables the gate before `auth.js`, the setup page and the fixture changes ships a dashboard whose every poll 401s, and a red unit suite.
**How to avoid:** Plan decomposition above; the switch plan is atomic. Run `tests/unit` and the route-inventory test before each push; run the debug container before pushing the switch.

### Pitfall 4: Per-test scrypt makes the suite 20 seconds slower
**What goes wrong:** Hashing in the function-scoped `test_client` fixture (about 107 tests × about 205 ms).
**How to avoid:** Session-scoped precomputed hash, directly minted cookie (Pattern 9). Only the auth tests exercise real hashing. Do not add a "weak scrypt params" knob to production code to speed tests up.

### Pitfall 5: `next` taken from the fragment URL, or an open redirect
**What goes wrong:** An htmx 401 for `/api/status/html` sets `next=/api/status/html`, so after login the browser lands on a bare HTML fragment. Or `next=//evil` / `/\evil` is honored.
**How to avoid:** `next` for HTMX comes from `HX-Current-URL` (path+query only, same host); `safe_next()` validated on both ends; tests for `//host`, `/\host`, `https://x`, `/login`, CR/LF.

### Pitfall 6: Hashing and verification on the event loop
**What goes wrong:** about 205 ms of CPU per attempt on the loop that also runs `process_reading` and the dashboard polls.
**How to avoid:** `await asyncio.to_thread(...)` for hash and verify. The limiter pre-check returns 429 before any hashing, which bounds how many worker threads an attacker can occupy. Add a `threading.Semaphore(2)` inside the worker function (a module-level `asyncio.Semaphore` would bind to one event loop, and TestClient creates loops per client). Cap input length at 1024 before hashing.

### Pitfall 7: Cookie flags that lock out plain-HTTP LANs
**What goes wrong:** `Secure` unconditionally (or `SessionMiddleware(https_only=True)`) makes login succeed and the next request anonymous.
**How to avoid:** `secure=request.url.scheme == "https"` (verified both ways). Behind a TLS proxy uvicorn only trusts `X-Forwarded-Proto` from `127.0.0.1,::1` by default `[VERIFIED: uvicorn Config in image: proxy_headers True, forwarded_allow_ips 127.0.0.1,::1]`; document `FORWARDED_ALLOW_IPS` for proxy users. Without it the cookie simply stays non-Secure and still works.

### Pitfall 8: Mobile nav overflow with two more items
**What goes wrong:** `_nav.html` already has up to seven items (Home, Label, Training, ROI, optional Calib, Config, Theme) in a 56 px bottom bar where each item is `flex: 1; min-width: 0` and labels are `white-space: nowrap` at 10 px. Two more items (nine total) leave about 36-45 px per item on 320-414 px screens, so labels like "Training" will clip.
**How to avoid:** UI-SPEC must decide icon-only or smaller labels for the new items on mobile (D-01 fixes that both are visible). Logout is a `<form>` containing a `<button class="nav-item">`: reset `form` margins and make the form a flex child (`display: contents` or equal `flex: 1`), otherwise it breaks the row.

### Pitfall 9: Existing integration suite may already depend on a reference image
**What goes wrong:** `test_smoke.py::test_dashboard_page` does `api.get("/")` and expects 200, but `routes/pages.py:43` returns a 303 when `/data/reference_raw.jpg` is absent, and `httpx.Client(...)` does not follow redirects by default. On a self-started fresh container it likely returns 303 today.
**How to avoid:** Run the integration suite once against the debug container before the change to separate pre-existing failures from auth regressions `[ASSUMED: not run this session; building the image and starting a suite container is minutes]`.

### Pitfall 10: Re-render status codes and password-manager friction
**What goes wrong:** Returning 200 with an error banner for a failed login; no username field means password managers will not offer to save.
**How to avoid:** Failed login → 401, throttled → 429 with `Retry-After`, validation error on setup → 400; include a visually hidden `autocomplete="username"` field with value `admin`; `autocomplete="current-password"` on login and `"new-password"` on setup/change; `Cache-Control: no-store` on these pages.

### Pitfall 11: Throttle counting the wrong events
**What goes wrong:** Counting 401s from expired-session polling (kiosk tab left open overnight) locks the owner out of their own login.
**How to avoid:** Only failed password/token checks are recorded. The limiter is not consulted for anonymous GETs or API 401s.

### Pitfall 12: Setup reachable while the container has no persistent `/data`
**What goes wrong:** Every recreate reopens `/setup`.
**How to avoid:** Warn at startup when `os.path.ismount('/data')` is false and no env seed is configured; README says to mount `./data:/data` (the compose file already does) or set `WATERMETER_ADMIN_PASSWORD`.

### 1. scrypt PHC hash/verify (parameters measured on the shipped image)
```python
# auth.py
import base64, hashlib, hmac, os

N_EXP, R, P = 15, 8, 3          # OWASP-listed equal-strength config; ~205 ms, 32 MiB on the image
_MAX_LN, _MAX_R, _MAX_P = 17, 16, 16

def _b64(b: bytes) -> str: return base64.b64encode(b).decode().rstrip("=")
def _unb64(s: str) -> bytes: return base64.b64decode(s + "=" * (-len(s) % 4))

def _derive(password: str, salt: bytes, ln: int, r: int, p: int) -> bytes:
    n = 1 << ln
    maxmem = 2 * 128 * r * (n + p + 2)          # default 32 MiB rejects N=2^15 on OpenSSL 3.0.2
    return hashlib.scrypt(password.encode("utf-8"), salt=salt, n=n, r=r, p=p, dklen=32, maxmem=maxmem)

def hash_password(password: str) -> str:
    salt = os.urandom(16)
    return f"$scrypt$ln={N_EXP},r={R},p={P}${_b64(salt)}${_b64(_derive(password, salt, N_EXP, R, P))}"

def verify_password(password: str, stored: str) -> bool:
    try:
        _, algo, params, salt_b64, hash_b64 = stored.split("$")
        kv = dict(item.split("=") for item in params.split(","))
        ln, r, p = int(kv["ln"]), int(kv["r"]), int(kv["p"])
        if algo != "scrypt" or ln > _MAX_LN or r > _MAX_R or p > _MAX_P:
            return False
        return hmac.compare_digest(_derive(password, _unb64(salt_b64), ln, r, p), _unb64(hash_b64))
    except Exception:
        return False
```

### 2. No-clobber create / replace with ownership fix
```python
import json, os, tempfile
from pathlib import Path

def _write_tmp(path: Path, data: dict) -> str:
    fd, tmp = tempfile.mkstemp(dir=path.parent, suffix=".tmp")      # created 0600
    try:
        with os.fdopen(fd, "w") as f:
            json.dump(data, f)
        if os.geteuid() == 0:                                       # docker exec runs as root (Dockerfile USER root)
            st = os.stat(path.parent)
            os.chown(tmp, st.st_uid, st.st_gid)
        return tmp
    except BaseException:
        os.unlink(tmp)
        raise

def create_once(path: Path, data: dict) -> bool:
    """True if we created it; False if someone else won (AUTH-02)."""
    tmp = _write_tmp(path, data)
    try:
        os.link(tmp, path)                                          # atomic, fails if path exists
        return True
    except FileExistsError:
        return False
    finally:
        os.unlink(tmp)

def replace(path: Path, data: dict) -> None:
    os.replace(_write_tmp(path, data), path)
```

### 3. Token + CSRF + gate core (spike-verified; condensed from the prototype)
```python
def sign(secret: bytes, issued: int, epoch: int) -> str:
    body = f"v1.{issued}.{epoch}"
    return body + "." + hmac.new(secret, body.encode(), hashlib.sha256).hexdigest()

def origin_ok(headers) -> bool:
    sfs = headers.get("sec-fetch-site")
    if sfs is not None:
        return sfs in ("same-origin", "none")
    origin = headers.get("origin")
    if origin is None:
```

```python
class FailureLimiter:
    WINDOWS = ((1, 1), (60, 5), (3600, 20))               # (seconds, max failures) per key
    def __init__(self, clock=time.monotonic): self._clock, self._lock, self._hits = clock, threading.Lock(), {}
```

### 6. `auth.js` (sketch)
```js
(function () {
  var HDR = 'X-Requested-With', VAL = 'watermeter';
  function same(u) { try { return new URL(u, location.href).origin === location.origin; } catch (e) { return false; } }
  function unsafe(m) { m = (m || 'GET').toUpperCase(); return m !== 'GET' && m !== 'HEAD' && m !== 'OPTIONS'; }
  function toLogin() {
    if (location.pathname === '/login' || location.pathname === '/setup') return;
    location.assign('/login?next=' + encodeURIComponent(location.pathname + location.search));
  }
  var _fetch = window.fetch;
  window.fetch = function (input, init) {
    var url = typeof input === 'string' ? input : input.url;
    var method = (init && init.method) || (typeof input !== 'string' && input.method) || 'GET';
    if (same(url) && unsafe(method)) { init = init || {}; var h = new Headers(init.headers || undefined); h.set(HDR, VAL); init.headers = h; }
    return _fetch.call(this, input, init).then(function (r) { if (r.status === 401 && same(url)) toLogin(); return r; });
  };
  var _open = XMLHttpRequest.prototype.open, _send = XMLHttpRequest.prototype.send;
  XMLHttpRequest.prototype.open = function (m, u) { this._wm = { m: m, u: u }; return _open.apply(this, arguments); };
  XMLHttpRequest.prototype.send = function () {
    var w = this._wm;
    if (w && same(w.u)) {
      if (unsafe(w.m)) this.setRequestHeader(HDR, VAL);
      this.addEventListener('loadend', function () { if (this.status === 401) toLogin(); });
    }
    return _send.apply(this, arguments);
  };
})();
```

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| First-visitor setup takeover on LAN | Elevation of Privilege | One-shot no-clobber write; optional setup token (AUTH-14); env seed closes the window; startup warning that setup is open |
| Concurrent `/setup` submits | Tampering | `threading.Lock` + `os.link` no-clobber |
| Brute force against `/login` | Spoofing | Failure-only sliding windows per IP (+ optional global), 429 + `Retry-After`, scrypt cost, 1024-char cap |
| Cross-site request forgery | Tampering | Origin/`Sec-Fetch-Site` check + required `X-Requested-With` on cookie-bearing `/api/*` writes; SameSite=Lax; no mutating GET |
| Login CSRF / logout CSRF | Tampering | Origin check on `/login`, `/setup`, `/logout` |
| Open redirect via `next` | Spoofing | `safe_next()` on every use |
| Session fixation/forgery | Spoofing | Server-signed tokens only, new token issued at login/setup/password change, HMAC compare |
| Cookie collision between instances | Spoofing/DoS | `wm_session_<instance_id>` |
| Tampered `auth.json` (huge scrypt params) | DoS | Clamp parsed `ln`/`r`/`p` before deriving |
| Reopened setup after corrupt or unreadable store | Elevation of Privilege | `UNAVAILABLE` state, fail closed |
| Root-owned auth file after `docker exec` | DoS | `chown` to parent owner; documented `-u watermeter` |
| Password in logs/URLs | Information Disclosure | Never log passwords; setup token and passwords only in POST bodies; `Cache-Control: no-store` on auth pages |
| Anonymous probing of route inventory | Information Disclosure | Default-deny before routing; `/docs`, `/openapi.json` disabled |
| Session cookie sniffing on HTTP LAN | Information Disclosure | Accepted and documented (TLS via reverse proxy is the answer); `Secure` set automatically over HTTPS |
