README.md: add a `## Authentication` section (anchor `#authentication`, the target of `auth.README_AUTH_URL`) after the Configuration section, written in plain language with example values only (for example `192.168.x.x`, `meter.example.lan`), covering:
- First visit: every page asks for an admin password on a fresh install; set it on the setup page (at least 8 characters). Until then only the setup page and `/health` answer.
- Upgrading: the same setup page appears once after updating; configuration and readings are unchanged and MQTT publishing to Home Assistant keeps running while no password is set (D-06, D-07).
- Sessions: logins last 30 days and renew while used; Account page for changing the password (logs out every other session); Logout in the navigation; each instance has its own session cookie, so several instances on one host do not interfere.
- Pre-seeding: `WATERMETER_ADMIN_PASSWORD` or `WATERMETER_ADMIN_PASSWORD_FILE` (Docker secret file) is used only while no password exists and is ignored afterwards.
- Setup token: `WATERMETER_SETUP_TOKEN_REQUIRED=1` adds a token field to the setup page; the token is printed in the container log (`docker logs <container>`) and changes on every start.
- Persistent data: the password lives in `./data/auth.json`; without a persistent `/data` volume the setup page returns after every container recreate.
