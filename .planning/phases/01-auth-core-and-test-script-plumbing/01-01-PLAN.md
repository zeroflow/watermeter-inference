Harden `AuthStore` in `watermeter/auth.py`:
- Three states with fail-closed parsing (RESEARCH Pitfall 2, deliberate deviation noted below). `state()` and `record()` share one `_load()` that calls `os.stat(path)`: `FileNotFoundError` means UNCONFIGURED; any other `OSError` means UNAVAILABLE. When the cache key `(str(path), st_mtime_ns, st_size, st_ino)` differs from the cached one, read and `json.loads` the file and validate it: a dict with `version == 1`, `password_hash` a str starting with `$scrypt$`, `session_secret` matching `^[0-9a-f]{64}$`, `instance_id` matching `^[0-9a-f]{8}$`, `epoch` an int (not bool) of at least 1, `created_at` a str. Any failure gives UNAVAILABLE and one `logger.error(f"Auth file {path} is unreadable or invalid ({reason}); refusing every request except /health. Fix or delete it to recover (see README).")` per cache key, never per request. Cache access is guarded by a `threading.Lock`. Deviation from RESEARCH Pattern 1, recorded in a code comment: a valid JSON file without `password_hash` is UNAVAILABLE, not UNCONFIGURED, because no code path writes such a file and no-clobber creation requires the path to be absent.
- `create` holds a module-level `_WRITE_LOCK = threading.Lock()` around "state is UNCONFIGURED, then link" and returns False for CONFIGURED and UNAVAILABLE (AUTH-02). `replace_password` holds the same lock.
- Extract `_write_temp(path: Path, data: dict) -> str` used by both writers: mkstemp in the same directory, write JSON, flush, fsync, and when `os.geteuid() == 0` call `os.chown(tmp, parent_stat.st_uid, parent_stat.st_gid)` using `os.stat(path.parent)` (docker exec runs as root because the Dockerfile has USER root; the entrypoint chowns /data to the app user, RESEARCH Pitfall 1); on any exception unlink the temp file and re-raise. After a successful write, drop the cache entry.

## Decisions made in this plan (Claude's discretion, within locked research)

- Setup-token env flag name: `WATERMETER_SETUP_TOKEN_REQUIRED` (the name suggested in D-09); accepted values 1, true, yes.
- Throttle is per client key only, with no separate global backstop (RESEARCH Open Question 1 left it optional). Behind a reverse proxy every client shares one IP, so the per-IP windows already act globally; a global counter would let a LAN attacker keep the owner throttled.
- A valid JSON auth.json without `password_hash` is UNAVAILABLE rather than UNCONFIGURED (RESEARCH Pattern 1 said UNCONFIGURED): no code writes such a file and the no-clobber `os.link` creation could never replace it, so treating it as unconfigured would open a setup page that cannot complete.
- Token prefix `wm1` instead of the research sketch's version prefix; same structure.
