`class AuthMiddleware` with `__init__(self, app: ASGIApp) -> None` and `async def __call__(self, scope, receive, send)`:
1. `scope["type"] == "lifespan"`: pass straight through to the app.
2. `scope["type"] == "websocket"`: send `{"type": "websocket.close", "code": 1008}` and return (the app has no websockets; default deny).
3. HTTP: read `path = scope["path"]` and `state = auth.get_store().state()`. When the store raises anything, treat the state as UNAVAILABLE (log once with `logger.exception`), so the gate fails closed instead of erroring.
4. UNAVAILABLE: only `/health` passes; every other path gets 503 (`JSONResponse({"success": False, "message": "Authentication store unavailable; see the container log"}, 503)` for `/api/` paths, `PlainTextResponse` with the same sentence otherwise).
5. CONFIGURED: `record = store.record()` and `issued = auth.session_issued_at(record, HTTPConnection(scope).cookies)`.
6. Allowlist via a module function `_is_allowed(state, path) -> bool` with exact, case-sensitive matches: UNCONFIGURED allows `auth.HEALTH_PATH`, `auth.SETUP_PATH` and paths starting with `auth.STATIC_PREFIX`; CONFIGURED allows `auth.HEALTH_PATH`, `auth.LOGIN_PATH`, `auth.LOGOUT_PATH` and the static prefix. Allowed paths and requests with a valid `issued` pass to the app. Method does not matter for the allowlist, so HEAD and OPTIONS behave like GET.
7. Otherwise call `_deny(...)`, which shapes the refusal by caller (locked 401 contract, AUTH-07): with header `hx-request: true` return an empty-body `Response(status_code=401, headers={"HX-Redirect": location, "Cache-Control": "no-store"})` where location is `/setup` when unconfigured, else `/login?next=` + `quote(auth.next_from_hx_current_url(headers.get("hx-current-url"), headers.get("host")), safe="/")` (the fragment URL itself is never used as next); for paths starting with `/api/` return `JSONResponse({"success": False, "message": "Authentication required", "setup_required": state is AuthState.UNCONFIGURED}, 401)`; otherwise `RedirectResponse(location, 303)` with location `/setup` when unconfigured, else `/login?next=` + `quote(auth.safe_next(path_with_query), safe="/")` where `path_with_query` is the path plus "?" plus the decoded `scope["query_string"]` when present. Unknown paths are denied the same way because the gate runs before routing.

  <action>
Extend `AuthMiddleware.__call__` so the HTTP order is exactly: store state, UNAVAILABLE handling, session lookup, CSRF check for unsafe methods, allowlist, session pass, deny (truth: fixed evaluation order).

CSRF (locked decision, AUTH-08), as a module function `_csrf_refusal(headers: Headers, method: str, path: str, has_session: bool) -> str | None` returning a short reason or None. It applies only to POST, PUT, PATCH and DELETE:
1. When `sec-fetch-site` is present, only `same-origin` and `none` pass (`same-site` is refused: other ports on the same host are same-site).
2. Else when `origin` is present: `null` is refused; an origin that, lowercased and without a trailing slash, is in `_allowed_origins()` passes; otherwise `urllib.parse.urlsplit(origin).netloc.lower()` must equal `headers.get("host", "").lower()` (netloc only, not scheme, so a TLS proxy without X-Forwarded-Proto still works). X-Forwarded-Host is never read.
3. Neither header present: treated as a non-browser client and allowed by this step.
4. When `has_session` is True and the path starts with `/api/`, the header `auth.CSRF_HEADER` must equal `auth.CSRF_HEADER_VALUE`, else refuse. `/login`, `/setup` and `/logout` therefore need only steps 1-3.
`_allowed_origins() -> frozenset[str]` reads `os.environ.get(auth.ALLOWED_ORIGINS_ENV, "")` on each call, splits on commas, strips whitespace and trailing slashes, lowercases, drops empty entries. A refusal returns `JSONResponse({"success": False, "message": "Cross-site request refused"}, 403)` and logs `logger.warning(f"Refused {method} {path}: {reason} (client {client_ip})")`, where client_ip comes from `scope.get("client")`.

Sliding refresh (D-17, AUTH-13): when `issued` is valid and `time.time() - issued > auth.SESSION_REFRESH_AFTER`, wrap `send` so that on the `http.response.start` message it inspects `MutableHeaders(scope=message).getlist("set-cookie")`; when none of them starts with `record.cookie_name + "="` it appends `auth.build_session_cookie(record, auth.issue_token(record), secure)` with `secure = scope.get("scheme") == "https"`. Skipping when the response already sets the cookie keeps logout (Max-Age=0) and the password change (new epoch) from being overwritten by a stale refresh.

Add the behavior-block cases to `tests/unit/test_auth_middleware.py`. Old tokens come from `auth.issue_token(record, now=time.time() - 16 * 86400)`; extract a refreshed token from the Set-Cookie header text and check it with `auth.verify_token`. The allowed-origins test sets the env var with monkeypatch.

## Decisions made in this plan (Claude's discretion, within locked research)

- The middleware is proven on a harness FastAPI app here and wired into the real app in Plan 04, so no push between plans can publish a gate without its setup page, shim and fixtures.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network client -> ASGI app | Every HTTP request is untrusted until the gate has checked state, CSRF and the session |
| cross-site page -> browser -> app | A foreign page can make the owner's browser send requests carrying the session cookie |
| reverse proxy -> app | A proxy may rewrite Host or terminate TLS, changing what the CSRF check sees |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-11 | Elevation of Privilege | AuthMiddleware gate | critical | mitigate | Default deny before routing for every path except the state allowlist; static, docs and unknown paths included; websocket closed 1008 |
| T-01-12 | Tampering | cookie-authenticated /api writes | high | mitigate | Origin/Sec-Fetch-Site check plus required `X-Requested-With: watermeter` (a cross-site page cannot set it without a CORS preflight the gate refuses); SameSite=Lax cookie |
